# DeskPet — Agent 监听桌宠 实施计划

## 一、目标

Python + tkinter 桌面宠物：透明背景、置顶、头顶状态气泡；实时监听终端里的 Claude Code / Codex / pi / Kimi CLI（Windows 原生 + WSL，可多选多监听）；气泡内可批准/拒绝审批请求；仪表盘管理监听目标与外观；五动画状态皮肤体系可扩展；不用 hooks，纯"进程发现 + 只读会话文件 tail + 终端窗口按键"实现；内存目标 40~80MB。

## 二、素材方案（已核实现状）

`assets/pets/default/` 已有 5 个 **WebM** + manifest.json，命名已规范为五状态：`walk`=工作中、`attack`=下达指令(批复发出)、`die`=中断待批复、`special`=完成庆祝×3、`sleep`=无任务。无需重命名，直接沿用为标准皮肤规范。

**转换管线**（tools/convert_skins.py，首次运行/导入皮肤时执行）：
- ffmpeg 抽帧 → Pillow 合成带透明索引的 GIF，落盘 `assets/cache/<skin>/<state>.gif`
- 统一缩放（默认高度 ~240px，可配）、抽帧到 ≤12fps；`frameSize:1000` 的原素材自动降采样
- ffmpeg 缺失时自动用 `imageio-ffmpeg`（pip 依赖，仅转换期使用）
- 运行时用 tkinter 原生 GIF 解码（惰性 `-index n` 逐帧 + LRU≤2 个动画缓存），静态模式=仅播第 0 帧

## 三、监听架构（已严格查证）

**发现层** agents/discovery.py：psutil 扫 Windows 进程（claude.exe / node+@anthropic-ai\claude-code / codex*.exe / kimi.exe 或 python+kimi-cli / node+pi-coding-agent）；每 5s 用 `wsl.exe -l -q` + `wsl -d <发行版> ps -eo pid,etimes,args` 扫 WSL 发行版。产出 AgentInstance{来源, pid, 类型, 启动时间}。

**解析层**（每类型一个 watcher，tail 会话文件，0.6s stat 轮询、增量读、partial-line 缓冲、每 agent 200 条 ring buffer；只绑定存活进程，不管历史会话）：

| Agent | 会话文件（实时落盘，已验证） | 工作中 | 完成 | 待批复检测 |
|---|---|---|---|---|
| Claude Code | `~/.claude/projects/<路径改写>/<uuid>.jsonl` | assistant 文本/tool_use | 静默+turn 结束 | 启发式：末尾 tool_use 无配对 tool_result 且文件静默>6s（气泡标注"推测"）；辅助 ai-title/last-prompt 做任务标题 |
| Codex | `~/.codex/sessions/年/月/日/rollout-*.jsonl` | task_started / CommandExecution | task_complete(含 last_agent_message) | 审批事件**不写 rollout**（已查证 0 命中）：尝试 tail `~/.codex/log/codex-tui.log` 找审批痕迹，失败则降级为"长时间无事件→气泡提示可能等待批复" |
| Kimi | `~/.kimi/sessions/<md5(cwd)>/<uuid>/wire.jsonl` | TurnBegin/ToolCall | TurnEnd | **精确**：`ApprovalRequest` 无对应 `ApprovalResponse` |
| pi | `~/.pi/agent/sessions/<路径编码>/*.jsonl` | assistant/toolCall | 静默 | pi 设计上无审批弹窗（已查证），标"无" |

**WSL**：会话文件经 `\\wsl$\<发行版>\home\<user>\...` 直接读（已验证可行），9P 慢故只 stat+增量读；用户主目录自动枚举。

**状态机**（全局聚合，优先级）：die(待批复) > special(刚完成,播3遍) > walk(工作中) > sleep(无任务)。多 agent 同时监听时气泡轮播，文本带 `[Codex]` 前缀；仪表盘可勾选哪些实例绑定气泡。

## 四、批复通道（actions/approve.py）

用户已选"聚焦终端+自动按键"：ctypes EnumWindows 定位该 agent 的宿主终端窗口（Windows 进程按 PID/console 匹配；WSL agent 匹配其 Windows Terminal 窗口标题）→ SetForegroundWindow → SendInput 发送键位：Codex 批准=`y`/拒绝=`Esc`；Claude 批准=`Enter`(默认 Yes)/拒绝=`Esc`；Kimi 批准=`Enter`/拒绝=`Esc`。键位表进配置可改。发送后播 attack 动画+气泡确认"已发送 y"。匹配失败时气泡提供"手动选择窗口"兜底（点击选择目标窗口并记住映射）。

## 五、UI

- **桌宠窗口**：overrideredirect + `-transparentcolor` 魔法色透明 + 可关置顶 + 跳过任务栏；左键拖拽、位置记忆；DPI 感知
- **气泡**：Canvas 自绘圆角+尾巴，按字体 measure 自适应换行（最大宽 280px、≤5 行、超长省略），字体族/字号/颜色/气泡缩放可配，随宠物整体缩放；待批复时内嵌 [批准][拒绝] Canvas 按钮 + 命令摘要
- **右键菜单**：互动(摸头→随机动画+台词)、仪表盘、监听目标子菜单、动态/静态、播放速度(0.5~3x)、换肤、退出
- **仪表盘**（深色扁平 ttk 主题）：Agent 实例表(来源/类型/PID/状态/最近活动/绑定)、字体与气泡设置、宠物设置(皮肤/缩放/速度/动态静态/置顶)、批复键位表、实时事件日志预览、皮肤导入向导（选 5 个 webm/gif → 校验 → 转换注册）；设置持久化到 config.json

## 六、内存策略

依赖仅 `psutil`(+转换期 `Pillow`/`imageio-ffmpeg`)；单 tk mainloop + 1 个监控线程(队列投递 UI 事件)；帧缓存 LRU≤2、空闲 5 分钟卸载；轮询频率可调；无 Qt/watchdog/托盘等重依赖。

## 八、已知风险与降级

- Codex 审批检测是短板（官方只走内存事件流）：log 尝试 + 降级提示，如实标注
- Claude"待批复"为启发式：去抖+标注"推测"，避免把长工具执行误报为 die
- WSL 9P 轮询限频防卡顿；transparentcolor 用近黑色减少边缘彩边
- 各 CLI 会话格式属内部格式，解析器按 type 字段容错解析，异常行跳过不影响运行
